# Feature audit, 2026-09-29

Read-only review by Codex CLI of every feature commit from 2026-09-29. Findings are tracked on the Kaneo RAM board; this is the evidence behind those cards.

## Ranked findings

1. Reopened replies lose the wrong-account warning

   - Bug: The original recipient headers are marked `@Transient`, so they disappear when an autosaved reply is reopened. The warning then has no address to compare against.
   - Location: [Composer.kt](../../src/main/kotlin/org/rampart/Composer.kt:203), [Composer.kt](../../src/main/kotlin/org/rampart/Composer.kt:387)
   - Reproduce: Start a reply to mail received through an alias, wait for autosave, close the composer, reopen the draft, and send from the account's default identity. The warning shown on the initial reply is now absent.
   - Fix: Persist the source recipient information with the server draft, or reload the referenced original message when reopening a reply and reconstruct these fields.

2. The update is never prefetched

   - Bug: `checkForUpdate()` immediately sets `barState` to `Waiting`. The staging effect then sees that exact state and returns without calling `Updates.stage()`. The UI claims the version is ready even though it has not been downloaded.
   - Location: [Main.kt](../../src/main/kotlin/org/rampart/Main.kt:1319), [Main.kt](../../src/main/kotlin/org/rampart/Main.kt:1354)
   - Reproduce: Run an older packaged Windows build, let the automatic check find a release, then inspect behavior before pressing Restart. No background staging occurs, and Restart has to download/install at that point.
   - Fix: Do not set `Waiting` until staging succeeds. Introduce a distinct Available or Staging state, or remove the `already` early return from the staging effect.

3. Calendar times ignore the selected display time zone

   - Bug: `formatTime` and `formatDateTime` convert an `Instant`, but deliberately leave a `ZonedDateTime` in its original zone. Calendar events use `ZonedDateTime`, so changing Language, Region and Time does not change their displayed time or sometimes even their displayed day.
   - Location: [Regional.kt](../../src/main/kotlin/org/rampart/Regional.kt:287), [Regional.kt](../../src/main/kotlin/org/rampart/Regional.kt:338), [CalendarPane.kt](../../src/main/kotlin/org/rampart/CalendarPane.kt:478)
   - Reproduce: Open an event stored in UTC, select America/Los_Angeles as the Rampart time zone, and compare its displayed hour. It remains in UTC.
   - Fix: Convert `ZonedDateTime` with `withZoneSameInstant(region.zone)` before deriving its date and clock. Keep `LocalDateTime` unchanged because it has no source zone.

4. Contact-history totals and date range can describe another person

   - Bug: The page rows remove JMAP's substring matches, but the received count, sent count, and oldest-message query do not. Searching for `bob@example.org` can count mail for `jimbob@example.org`, and can show the wrong first-contact date.
   - Location: [Jmap.kt](../../src/main/kotlin/org/rampart/Jmap.kt:2101), [Jmap.kt](../../src/main/kotlin/org/rampart/Jmap.kt:2121), [Jmap.kt](../../src/main/kotlin/org/rampart/Jmap.kt:2125)
   - Reproduce: Have mail involving both `bob@example.org` and `jimbob@example.org`, then open Bob's history. The visible rows are filtered exactly, but the header totals and first date include Jimbob's messages.
   - Fix: Fetch and exact-filter the matching headers when calculating statistics, or compute the statistics while paging the exact rows rather than trusting JMAP text-query totals.

5. The tray unread badge counts excluded shared mailboxes

   - Bug: The badge sums every inbox in the `mailboxes` map. That map includes shared accounts regardless of whether the user excluded them from unified views, while the sidebar's All inboxes uses the selected account set.
   - Location: [Main.kt](../../src/main/kotlin/org/rampart/Main.kt:747), [SharedMailboxesUi.kt](../../src/main/kotlin/org/rampart/SharedMailboxesUi.kt:98)
   - Reproduce: Add a shared mailbox with unread mail, exclude it from unified views, and compare the All inboxes count with the tray or taskbar badge. The badge still includes it.
   - Fix: Calculate the badge from the same `unifiedSessions` account set as the sidebar, or explicitly restrict it to signed-in primary sessions if that is the intended contract.

6. Dragging files and inspecting the clipboard can freeze the UI thread

   - Bug: Paste performs clipboard flavor access on the Compose event thread before launching its background work. Drop handling also calls `Files.isRegularFile` and `Files.isDirectory` directly inside `onDrop`. Clipboard providers and disconnected network-mounted paths can block.
   - Location: [Composer.kt](../../src/main/kotlin/org/rampart/Composer.kt:834), [Composer.kt](../../src/main/kotlin/org/rampart/Composer.kt:839), [Composer.kt](../../src/main/kotlin/org/rampart/Composer.kt:905), [Paste.kt](../../src/main/kotlin/org/rampart/Paste.kt:61)
   - Reproduce: Copy a file from a slow shell extension, or drop a file URI from an unavailable network mount. The composer window can stop repainting while the flavor or filesystem checks finish.
   - Fix: Capture only the event or `Transferable` on the UI thread, then perform flavor reads, URI conversion, and all filesystem probes on `Dispatchers.IO`.

7. Spell check silently assumes American English

   - Bug: The checker is always constructed with `AmericanEnglish`, independently of the Language setting. On a computer using another language, Auto still underlines ordinary non-English prose as misspelled.
   - Location: [SpellCheck.kt](../../src/main/kotlin/org/rampart/SpellCheck.kt:343), [Regional.kt](../../src/main/kotlin/org/rampart/Regional.kt:179)
   - Reproduce: Use a German or French system locale, leave Language on Auto, and type a normal sentence in that language. Nearly every word receives a red underline.
   - Fix: Either select a LanguageTool language from the resolved regional language or state clearly in settings that checking is English-only and default it off for unsupported locales.

8. Offline contact history omits Bcc recipients

   - Bug: Server-backed history explicitly includes Bcc, but `Summary.recipients` stores only To and Cc. Once the history falls back to the local copy, messages sent to the person exclusively through Bcc disappear from both rows and totals.
   - Location: [Jmap.kt](../../src/main/kotlin/org/rampart/Jmap.kt:2094), [Jmap.kt](../../src/main/kotlin/org/rampart/Jmap.kt:2300), [Store.kt](../../src/main/kotlin/org/rampart/Store.kt:1524)
   - Reproduce: Send a message with a person only in Bcc, allow Rampart to cache it, disconnect the account, then open that person's history. The message is absent.
   - Fix: Include normalized Bcc addresses in the locally stored recipient set when the backend supplies them.
