Your mail and your whole mail server, in one native desktop window.

A free, open source desktop mail client for Windows and Linux. Built for Stalwart, and happy on anything else.

Download Source on GitHub

Apache 2.0. No account, no telemetry, no subscription.

Built for Stalwart

Rampart is designed against the Stalwart mail server first. Stalwart speaks JMAP, and JMAP is what makes the second half of this application possible: your account settings and your server settings, managed from the same window as your mail.

IMAP can move messages and very little else. It has no way to carry your filter rules, your aliases, your vacation responder, your app passwords or your server's own configuration, so every IMAP client, however good it is, leaves nine tenths of a modern mail server invisible and sends you to a browser for the rest.

TodayBeing built
Mail Read, write, send, search, file, offline
Your account Sieve filter rules with a builder, vacation responder, signatures, contacts, quota App passwords, API keys, aliases
Your server Accounts, domains, DKIM, the mail queue, certificates, TLS, listeners, logs

The account and server screens are rendered from the server's own published schema rather than hand written, so they stay correct when Stalwart adds a field.

And it works on anything else

Type your email address and Rampart finds the rest. It asks what your domain publishes about itself, tries JMAP first and falls back to IMAP, and signs in with the first server that answers. There is a box for the hostname if your domain says nothing, and most people will never open it.

Reading, writing, sending, searching, folders, attachments and flags all work against any IMAP and SMTP server that takes a password. What the protocol cannot do is absent with a sentence saying why, never a button that fails.

What it does today

Reading

Threaded conversations, a unified inbox across accounts, instant offline search, and push over the JMAP WebSocket. Pictures in the flow, remote images held per sender, links confirmed before they open.

Knowing what a message is

A word above anything that cannot prove who sent it, from the SPF, DKIM and DMARC results your server already recorded. Trackers named rather than silently blocked.

Writing

Bold, italic, links, lists and inline pictures. Recipient autocomplete from your address book and your own mail. Templates, read receipts, and undo-send on a timer you choose.

Keeping a mailbox

Star, tag, archive, spam, trash, one at a time or in a batch, all undoable. Snooze a message until later. Create, rename, nest and delete folders.

Filters, as Sieve

Built in the interface or written by hand, in the format your webmail already reads, so a rule made in either one opens in the other.

Eighteen themes

The window's title bar included. Keyboard shortcuts with the list on a single key, a command palette, and passwords in the operating system's credential store.

Install it

Windows. Paste this into PowerShell:

irm https://github.com/thejdubb02/rampart/releases/latest/download/install.ps1 | iex

It trusts the signing certificate, installs Rampart and starts it. One admin prompt, the first time on each machine, and every update after that is silent. Do not double-click the .msix: Rampart is signed with its own key rather than a certificate from a public authority, and Windows will not install a package whose signer it does not know yet.

Linux. Take the .deb from the latest release.

macOS is not built yet. An unnotarised build is worse than none, and notarising needs a paid Apple account.

What it sends, which is nothing

Rampart talks to your mail server and to GitHub when it checks for an update. There is no account to make, no analytics, and no server of ours in the middle of your mail. Passwords go to the operating system's credential store.

One feature genuinely cannot work from a desktop application alone, which is knowing whether a message you sent was opened, because that needs somewhere on the web a picture can be fetched from. That server is in the repository, it is optional, you run it yourself, and with it unset the feature is visibly unavailable rather than quietly broken.
